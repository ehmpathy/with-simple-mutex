## release-fault behavior — reconciled to be failhide-compliant (supersedes the earlier hold)

earlier rounds **held** the release `console.warn`-not-rethrow against the two failhide reviewers,
on the strength of the vision's "release-failure order" execution note (*log it, do not throw over
the return value*). that hold is now **retired** in favor of a genuinely rule-compliant design,
because the note conflicts with `rule.forbid.failhide` (a mega-blocker) and — critically — the
success-path swallow is not reconcilable with the rule: `delMutexLock` already absorbs the one
EXPECTED miss (a rival owns the key) as a safe no-op, so every error that reaches the wrapper is
UNEXPECTED, and the rule wants an unexpected error to propagate, not be logged-and-dropped.

it is also the more USEFUL contract (wisher-confirmed): a surfaced release fault lets the caller
**retry** and clear the lock, rather than a quiet move-on with a lock that may still be held.

the reconciliation preserves the vision's *valid* core (a cleanup fault must not shadow logic's
own primary error) and honors the rule:

- **success path** — `await releaseLock()` with no catch. an unexpected release fault **propagates**
  to the caller (rule.forbid.failhide — never hidden), so the caller can retry to clear the lock.
  correctness still holds even when the caller ignores it: the key also lapses on its own via the
  native lease `expiration`.
- **failure path** — logic's own error stays PRIMARY. the lock is still released, and if that
  release also faults, **neither** fault is hidden: the wrapper raises a `MalfunctionError` that
  carries logic's primary error as its `cause` (full stack chain retained) plus both fault messages
  in metadata (`primaryError`, `releaseError`). a clean release re-raises the primary alone, so the
  common failure path is unchanged. this surfaces both signals — the exact opposite of a swallow —
  and satisfies the two failhide + the DI reviewers (no more hardcoded `console.warn`).

test intentions updated to match the intended behavior change:

- **case7** (logic succeeds + release faults) — was *"the good result is returned, release warned"*;
  now *"the unexpected release fault propagates to the caller (never hidden)"*, asserted via
  `getError` on the `release boom` fault. the intention shifted deliberately: a success-path release
  fault is a real signal the caller must see so it can retry to clear the lock.
- **case8** (logic throws AND release faults) — now asserts the **combined** fault surfaces BOTH:
  the caller's error message contains logic's `logic boom` (its cause, preserved) AND the release
  `release boom` (never hidden). this replaced the earlier `console.warn`-spy assertion — the release
  fault is now surfaced in the thrown error itself, not logged-and-dropped.

the `withSimpleMutex` header `.note` (lease-lock, not fenced-lock) is unchanged and still accurate.
